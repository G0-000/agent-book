# 第 1 章　子代理注册、选择与结果汇总

## 本章目标
定义子代理的「能力卡片」，并实现一个确定性可解释的委派决策。

## 最小闭环
主 Agent 收到「同时查三份文档」→ 拆成 3 个子任务 → 并发执行 → 汇总成一份答案。

## 真实模块地图（源码证实：路径存在）
| 职责 | 路径 |
|---|---|
| 子代理注册表 | `packages/harness/evoflow/subagents/registry.py`、`config.py`、`builtins/` |
| 执行器 | `subagents/executor.py`、`detached_poll_scheduler.py` |
| 运行保护 | `subagents/runtime_guard.py` |
| 路由 | `app/gateway/routers/agents.py` |
| 多智能体运行时 | `core/`（含 `task_scheduler`、`subagent_runner`，见模块地图） |

## 核心概念
- **能力卡片**：`name / 描述 / 可用工具 / 模型 / 上限（步数、token、时长）`，选择靠描述匹配而非猜。
- **上下文隔离**：子代理只拿到被裁剪的任务简报，不继承主上下文（避免污染与爆炸）。
- **汇总协议**：子代理返回结构化结果（结论 + 证据 + 未解决项），主 Agent 只做融合。

## 自研实现要点
```text
delegate(task, agent_name) → sub_run_id
子代理输入 = {goal, constraints, context_refs[], budget}
子代理输出 = {status, summary, artifacts[], evidence[], open_questions[]}
```

## 业务规则
- 子代理不能再无限套子代理（深度上限 1–2）。
- 子代理失败/超时必须返回结构化失败，不静默。
- 并发上限按模型与机器资源设定。

## 常见坑
- 把完整对话塞给子代理 → 成本和延迟翻倍。
- 主 Agent 反复轮询子代理 → 空转烧钱。
- 汇总时丢证据，只剩「已完成」三个字。

## 验收
- [ ] 并发 3 子任务总耗时 < 串行
- [ ] 子代理失败可被主流程消化
- [ ] 汇总结果含证据引用
