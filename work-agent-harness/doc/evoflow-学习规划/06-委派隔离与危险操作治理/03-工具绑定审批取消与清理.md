# 第 3 章　会话工具绑定、审批、取消与清理

## 本章目标
让「这一轮能用哪些工具」「哪些要问人」「人不在怎么办」都有明确答案。

## 最小闭环
会话启用只读工具集 → 请求写操作 → 弹出审批 → 批准后执行一次 → 会话结束回收全部句柄。

## 真实模块地图（源码证实：路径存在）
| 职责 | 路径 |
|---|---|
| 会话工具绑定 | `packages/harness/evoflow/session_tool_binding/` |
| 审批服务 | `agents/tool_approval_service.py`、`approval.py`(execution_security)、`persist.py`、`status.py` |
| 审批暂停/恢复 | `agents/tool_approval_pause_registry.py`、`tool_approval_resume.py` |
| 审批配置/黑名单 | `agents/tool_approval_config.py`、`tool_approval_denylist.py` |
| 审批轨迹 | `agents/tool_approval_trace_log.py` |

## 核心概念
- **绑定是白名单**：会话开始时确定工具集，中途不动态扩权。
- **审批粒度**：一次性 / 本次会话 / 永久（按参数指纹授权）。
- **挂起态**：run 进 `waiting_approval`，超时策略（拒绝 / 保持 / 通知）。
- **清理**：会话关闭时撤销绑定、终止子进程、释放沙箱与浏览器。

## 自研实现要点
```text
binding(session_id, tool, granted_by, scope, expires_at)
approval(id, run_id, tool, args_digest, decision, actor, decided_at)
恢复：带 approval_id → 校验 args_digest 一致 → 只执行一次
```

## 业务规则
- 参数变化即视为新审批（防「批了 rm a，跑了 rm b」）。
- 拒绝也是终态，模型应收到可解释的拒绝原因。
- 审计日志不可被 Agent 修改。

## 常见坑
- 审批后重放整轮 → 重复副作用。
- 只按工具名审批不看参数 → 权限被放大。
- 清理不彻底 → 下一会话继承上一个的句柄。

## 验收
- [ ] 参数指纹不一致时重新弹审批
- [ ] 恢复执行严格一次
- [ ] 会话结束无残留进程/端口
