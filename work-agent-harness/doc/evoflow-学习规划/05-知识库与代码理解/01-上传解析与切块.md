# 第 1 章　上传解析与切块 / Parse and Chunk

## 本章目标
把任意格式的文件变成「可检索、带上下文、可回溯」的片段。

## 最小闭环
上传 PDF → 解析出文本与页码 → 切成 500–800 字片段并带标题路径 → 落库 → 能被检索到。

## 真实模块地图（源码证实：路径存在）
| 职责 | 路径 |
|---|---|
| 解析 | `packages/harness/evoflow/knowledge/parser.py`、`processor.py` |
| 切块 | `knowledge/chunker.py`、`wiki_chunker.py` |
| 上传管理 | `uploads/`、`app/gateway/routers/knowledge.py`、`media_assets.py` |
| 索引构建 | `knowledge/index_builder.py`、`llm_indexer.py`、`local_source.py` |

## 核心概念
- **解析质量决定上限**：表格、双栏 PDF、扫描件需要不同策略（OCR 兜底）。
- **切块策略**：按结构切（标题/段落/代码块）优于按字数硬切。
- **元数据三件套**：`source_path`、`section_path`（如 `3.2 > 违约金`）、`char_range`。

## 自研实现要点
```text
chunks(id, doc_id, source_path, section_path, seq, text, tokens, hash)
去重：hash(text) 相同则不重复入库；文件更新时按 doc_id 批量替换
```

## 业务规则
- 单文件超限（如 200MB）拒绝并提示。
- 扫描件必须走 OCR 并标记 `needs_ocr`。
- 切块不允许切断代码块/表格行。

## 常见坑
- PDF 双栏按行读 → 语义交错。
- 切块过小 → 检索命中但上下文不足。
- 不存 `section_path` → 回答无法定位。

## 验收
- [ ] 表格内容可被检索
- [ ] 文件更新后旧块被清理
- [ ] 每块可回溯到页码/段落
