# 第 2 章　协作账本、团队分工、任务中心

## 本章目标
多个 Agent（或人 + Agent）协作时，需要一个**唯一可信的账本**记录「谁在做什么、做到哪」。

## 最小闭环
主 Agent 分派 2 个子任务给不同 Agent → 账本记录指派与状态 → 任务中心展示 → 完成后汇总。

## 真实模块地图（源码证实：路径存在）
| 职责 | 路径 |
|---|---|
| 协作域 | `packages/harness/evoflow/collab/`（含 `agent_assignment.py`、`conversation_scope.py`、`authorize_execution.py`） |
| 任务状态与持久化 | `collab/conversation_persist.py`、`persistence/` 中 task/goal 仓库 |
| 路由 | `app/gateway/routers/collab.py`、`routers/meetings.py` |
| 会议（多 Agent 讨论） | `a2a/meeting_tool_speak.py`、`a2a/meeting_conclude.py` |

## 核心概念
- **账本（ledger）**：append-only 的事件流（指派/开始/进度/阻塞/完成），状态由事件推导。
- **指派（assignment）**：任务 → Agent，含能力匹配与负载考虑。
- **会话作用域**：子任务有自己的会话，避免相互看到内部推理。

## 自研实现要点
```text
events(run_id, ts, actor, type, payload)  -- append-only
task_state = fold(events)                 -- 可重建，不双写
```

## 业务规则
- 账本只追加，不改写历史。
- 同一任务不能同时有两个「进行中」负责人。
- 阻塞必须写明「等什么」，否则视为无效状态。

## 常见坑
- 状态双写（事件 + 表）→ 不一致。
- 子任务共享同一个会话 → 上下文互相污染。
- 任务中心展示的是模型自述而非真实状态。
