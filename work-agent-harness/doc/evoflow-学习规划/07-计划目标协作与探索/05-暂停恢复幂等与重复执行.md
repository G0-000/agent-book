# 第 5 章　暂停恢复、幂等与重复执行

## 本章目标
让「中断后继续」不产生重复副作用——这是长任务系统最容易翻车的地方。

## 最小闭环
执行到第 3 步被暂停 → 恢复 → 第 1、2 步不重跑 → 第 3 步从断点继续。

## 真实模块地图（源码证实：路径存在）
| 职责 | 路径 |
|---|---|
| 续跑子任务会话 | `packages/harness/evoflow/collab/continue_subtask_session.py` |
| 计划守卫/文档 | `agents/middlewares/`（plan guard / plan doc） |
| 检查点 | `agents/checkpointer/`（见 Part 2） |
| 协作状态 | `collab/conversation_persist.py` |

## 核心概念
- **幂等键**：`(run_id, step_id, action_type)`；重复调用先查是否已有成功记录。
- **恢复点**：只从「已提交的检查点」恢复，不从未提交的内存状态恢复。
- **副作用分级**：只读可随意重放；写操作必须幂等键；外部通知必须去重。

## 自研实现要点
```text
effects(key, status, result_ref, created_at)  -- 唯一索引 key
执行前：if effects.exists(key) and status=done → 复用结果
```

## 业务规则
- 恢复不重放「已成功」的步骤。
- 暂停时必须落盘「当前步骤 + 已完成步骤集合」。
- 外部通知（邮件/IM）单独记投递记录。

## 常见坑
- 用消息 id 当幂等键 → 重试生成新 id。
- 只在内存记「做过」→ 重启全丢。
- 恢复时重放整轮 → 重复发消息、重复写文件。

## 验收
- [ ] 暂停/恢复后副作用次数不变
- [ ] 幂等键冲突返回旧结果而非报错
- [ ] 通知类动作有独立投递记录
