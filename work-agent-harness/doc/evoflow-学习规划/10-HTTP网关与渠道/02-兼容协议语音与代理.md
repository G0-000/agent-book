# 第 2 章　兼容协议、语音与 OpenAI/LangGraph 代理

## 本章目标
一套内核，多种协议出口：让 Vercel AI SDK、OpenAI SDK、LangGraph 客户端都能接。

## 最小闭环
OpenAI 兼容 `/v1/chat/completions` 调一次 → 流式返回 delta → 工具调用事件也能透出。

## 真实模块地图（源码证实：路径存在）
| 职责 | 路径 |
|---|---|
| OpenAI 兼容编解码 | `backend/app/gateway/openai_stream_encode.py`、`openai_stream_normalize.py`、`routers/openai_compat_models.py`、`openai_compat_apps.py` |
| AG-UI 编解码 | `agui_stream_encode.py`、`agui_stream_normalizer.py` |
| v4 协议投影 | `v4/agui_to_v4_projector.py`、`v4/hydration.py`、`v4/command_inbox.py`、`v4/conversation.py`、`v4/coalesce.py` |
| SSE 整形 | `sse_slim.py`、`sse_ui_normalize.py` |
| LangGraph 代理 | `routers/langgraph_proxy.py`、`lazy_langgraph.py` |
| 语音 | `app/gateway/speech/`、`routers/media_settings.py` |

## 核心概念
- **投影（projection）**：内部事件是事实源，外部协议只是投影；不要反向依赖外部格式。
- **事件合并（coalesce）**：高频 token 合并成批，降低前端重渲染压力。
- **hydration**：客户端重连时按「已投影到哪」补发，而不是重放全部。
- **协议版本化**：v4 与 AG-UI 并存，说明升级必须可并行。

## 自研实现要点
```text
Event{seq, run_id, type, payload}
Projector: Event → ProtocolFrame (agui | v4 | openai | sse)
Hydrator: (run_id, last_seq) → 补发 frames
```

## 业务规则
- 任何协议适配器不得改写事件语义（只改形状）。
- OpenAI 兼容层不暴露内部工具名。
- 语音链路单独限流。

## 常见坑
- 在投影层做业务判断 → 各协议行为不一致。
- 事件 seq 不单调 → 补发乱序。
- 兼容层把错误码吞成 200。

## 验收
- [ ] 同一 run 在三种协议下语义一致
- [ ] 重连补发无重复无丢失
- [ ] 错误码可区分
