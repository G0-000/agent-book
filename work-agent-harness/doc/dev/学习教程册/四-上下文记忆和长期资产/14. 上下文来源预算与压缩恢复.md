## 场景

你在 CLI 里连着问了 30 轮，每轮都让 Agent 读几个文件。到第 25 轮左右，Agent 开始忘事：它不记得第一轮你定的命名规范，还把前面读过的文件又读了一遍。

更糟的是另一个场景：第 31 轮直接报错——**上下文塞满了**，模型拒绝请求。

本章要解决的就是这两件事：
1. 上下文快满了，怎么**在用户察觉前**把旧内容压掉；
2. 压掉之后，哪些东西**必须留下**（你定的规范、已经改过的文件），哪些可以丢（读过一遍的原文）。

## 本章要完成的功能

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 按字符数估算，而模型按 token 计费 | 估算偏乐观，压得不够，仍然超限 |
| 压缩在前台同步做 | 每轮都多一次模型调用，用户等得更久 |
| 折叠时不分轻重 | 把你刚定的规范一起折掉，比不折更糟 |
| ToolMessage 越积越多 | 一个大文件读三遍，直接把预算吃光 |
| 折叠后没有标记 | 事后查不出"这轮为什么少了两条消息" |

| ③ 折叠执行 | `agents/middlewares/context_compaction_middleware.py`（1500 行）：`:89` `compaction_folded_this_call()`、`:93` `compaction_fold_msg_counts()`、`:97` `last_bound_model_messages()` | 真正的折叠动作与结果回读 |

| ⑤ 摘要与缓存 | `context/tool_result_summarizer.py`、`tool_summary_prompts.py`、`context_ref_lru.py`、`file_read_cache.py` | 把 Tool 结果换成摘要；读文件走 LRU |

逐层追读要点：

1. **入口**：谁在模型调用前算预算（不是用户触发，是请求装配处）。
2. **调用者**：谁把 job 放进队列、谁消费队列（前台 vs 后台线程）。
3. **核心决策**：折叠的阈值是什么、保留哪几条（`last_bound_model_messages` 读的就是"模型实际收到的那一版"）。
4. **状态**：job 存哪、折叠计数存哪、跨轮怎么读回来。
5. **返回**：折叠后如何通知上层"这次折了几条"。
6. **证据**：`compaction_fold_msg_counts()` 返回 `(before, after)`，这就是可观测证据。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 预算口径 | token（`ModelCallOverheadEstimate`） | 折叠触发仍是字符（`MAX_CONTEXT_CHARS=12000`），但**记录**用 token 估算 |
| 压缩时机 | 队列 + 后台（`ContextCompactionQueue`） | 同步，`before_model` 内直接折 |
| 折叠实现 | 1500 行中间件，含分级、冷却、多轮 | `pinned` 分级 + 单函数 `_fold_summary`，无冷却/多轮 |
| Tool 历史 | `tool_history_merge.py`（299 行）+ 老化队列 | 同文件去重（`plan_tool_history_merge`），无冷区老化 |
| 摘要来源 | 模型生成（`tool_result_summarizer.py` + `tool_summary_prompts.py`） | 本地拼接文本，无模型调用 |
| 缓存 | `context_ref_lru.py`、`file_read_cache.py` | 无 |
| 可观测 | `compaction_fold_msg_counts()` / `last_bound_model_messages()` | `compaction_fold_detail()`（FoldRecord）+ `compaction_last_bound_estimate()` |

**一句话差异**：原版是"预算驱动的异步压缩系统"，本项目是"字符阈值触发、token 可观测、pinned 可保留的同步折叠"。前者面向多用户长会话，后者够 CLI 自用。

### 1. 请求级 token 估算（`context/token_budget.py`）

原版用真实 tokenizer，本仓要离线可跑，所以默认 `len(text)//3`，但接口留成可插拔：

```python
def default_estimator(text: str) -> int:
    """默认估算：按字符数除以 3，空文本记 0。"""
    stripped = (text or "").strip()
    if not stripped:
        return 0
    return max(1, len(stripped) // DEFAULT_CHARS_PER_TOKEN)   # 3 字符 ≈ 1 token


def estimate_request_tokens(
    messages: Iterable[Any],
    *,
    system_prompt: str = "",
    estimator: Estimator | None = None,
) -> TokenEstimate:
    """估算"这一轮请求"的 token 开销：系统提示 + 全部消息。"""
    system_tokens = estimate_tokens(system_prompt, estimator=estimator)
    message_tokens = sum(
        estimate_tokens(_message_text(message), estimator=estimator) for message in messages
    )
    return TokenEstimate(
        system_tokens=system_tokens,
        message_tokens=message_tokens,
        total_tokens=system_tokens + message_tokens,
        estimator="custom" if estimator is not None else current_estimator_name(),
    )
```

技术点：估算器用 `ContextVar` 存，测试可临时替换、跑完 `reset` 复原，不会污染下一次调用；工具 schema 的 token 在本篇视为固定开销，不参与折叠决策。

### 2. 折叠记录与 pinned（`context/compaction_state.py`）

折叠要能回答"为什么少了两条"，所以每次折叠写一条 `FoldRecord`：

```python
@dataclass(frozen=True)
class FoldRecord:
    before: int                 # 折叠前条数
    after: int                  # 折叠后条数（pinned + 摘要 + recent）
    folded: int                 # = before - after
    merged_tool_messages: int   # 同文件工具结果合并了几条
    pinned_kept: int            # 被钉住、原样保留几条
    total_tokens: int           # 折叠后这一版的估算
    estimator: str
    folded_ids: tuple[str, ...]


def pin_message(message: Any, *, reason: str = "") -> None:
    """就地给消息打钉：additional_kwargs["pinned"] = True"""
    kwargs = getattr(message, "additional_kwargs", None)
    if isinstance(kwargs, dict):
        kwargs[PIN_KEY] = True
        if reason:
            kwargs["pinned_reason"] = reason


def split_pinned(messages):
    """折叠前把消息拆成 (被钉住, 可折叠)，各自保持原顺序。"""
    pinned, rest = [], []
    for message in messages:
        (pinned if is_pinned(message) else rest).append(message)
    return pinned, rest
```

技术点：pinned 不在折叠候选里，所以第 16 章注入的记忆（`pin_message` 打过钉）永远不会被第 14 章的折叠吃掉——这是第 18 章能跨能力断言的前提。

### 4. 折叠中间件接线（`middleware/context_compaction.py`）

```python
class ContextCompactionMiddleware(AgentMiddleware):
    def before_model(self, state, runtime):
        if consume_skip_compaction_once():          # 一次性跳过（工具结果刚回来那轮）
            return None
        messages = list(state.get("messages", []))
        if _total_chars(messages) <= MAX_CONTEXT_CHARS:   # 12000 字符阈值
            return None
        if len(messages) <= KEEP_RECENT_MESSAGES:         # 只剩 6 条就别折了
            return None

        head, recent = messages[:-KEEP_RECENT_MESSAGES], messages[-KEEP_RECENT_MESSAGES:]
        pinned, foldable = split_pinned(head)             # 钉住的不折
        merge_drop_ids, merged_tools = plan_tool_history_merge(foldable)

        removals = [RemoveMessage(id=m.id) for m in foldable if m.id]  # 删旧消息
        summary = HumanMessage(content=_fold_summary(summarized), name="context_summary")

        bound = pinned + [summary] + recent
        estimate = estimate_request_tokens(bound)
        _last_bound.set(estimate)                          # 记录"模型实际看到的那版"
        _fold_counts.set((len(messages), len(bound)))
        record_fold(before=len(messages), after=len(bound), ...)
        return {"messages": removals + [summary]}
```
