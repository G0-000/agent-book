# M5 — 计划、协作、长任务与自动化

## 本章目标

把复杂任务当作持久化、有状态、可恢复的流程来学习。先分清计划、goal、协作状态、工具执行 scheduler 和时间触发/automation，再追完整的恢复和重复执行语义。

## 源码概念纠偏

- EvoFlow 根 `plans/` 是 Plan Bundle/第三方计划连接器，不等同于任务 DAG。
- 任务计划/协作生命周期主要看 `collab/`（包括 task plan storage）、`agents/goal/` 和实际调用者。
- EvoFlow `scheduler/` 主要是工具执行/调度能力，不等于 cron。
- 定时自动化需要追 `admin/automation_schedule.py`、Gateway automation runner、`proactive/schedule.py` 等真实入口；`automation/` 下模块职责也要沿调用点核实。

## 阅读入口

| 领域 | EvoFlow 路径 | AgentFlow 对照 |
|---|---|---|
| Goal/计划循环 | `agents/goal/`、`collab/` | `agents/goal/`、`plans/` |
| 任务存储/协作 | `collab/`、task state services | `collab/`、plan repositories |
| 工具执行调度 | `scheduler/`、tool executor | `scheduler/`（需核对语义差异） |
| 时间任务 | admin/Gateway/proactive schedule、automation tools | `scheduler/cron.py`、CLI automation |
| 持久化/恢复 | checkpoints、task/session repositories | SQLite repositories、checkpoint provider |

## 四级学习

### 核心代码讲解清单

沿真实调用链讲解 `agents/goal/` 的 graph/state/judge 或 loop、`collab/` 的 task plan storage 和 state transition、`scheduler/` 的 executor/retry、定时触发入口与 automation runner、相关 persistence/checkpoint。特别标清对象 ID、状态机合法转换、持久化事务边界、重启后的恢复点，以及每条实现的调用者和测试。

### L1 入门闭环

用 fake model 生成两步 plan，依赖关系固定；完成第一步后暂停，恢复并执行第二步。验证 state transitions 不允许跳转或重复完成。

### L2 基础能力

加入任务分解/验收、goal status、持久化 plan、checkpoint、失败状态、重试、超时、取消和单个定时 job。写明每个状态由谁更新、何时提交。

### L3 完整功能

盘点 EvoFlow 中 collaboration/peer/task ledger、Plan Bundle、goal loop/judge、task state、tool execution queue、retry policy、automation tool、定时触发、proactive workflow 和后台作业生命周期。逐项核对 worker ownership、跨进程状态、幂等键、结果/产物、通知和 operator 管理入口。AgentFlow `plans/` 与 EvoFlow `plans/` 不可因同名而假定对齐。

### L4 高级边界

验证进程重启、两 worker 抢同一任务、重复投递、任务 lease 过期、部分步骤已产生外部副作用、取消竞争、时区/DST/cron 变更、schedule 更新/删除、孤儿任务、失败重试风暴和审计。
