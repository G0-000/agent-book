# Agent 学习版 v2：篇 · 章 · 节规划

> 状态：规划稿。现有正文不删除、不立即替换；先按本规划建立 v2 骨架，并用「上下文」「长期记忆」两篇做样板。

## 1. 这次重排要解决什么

现有 13 部分是按 EvoFlow 的模块目录切的：最小闭环、持久化、工具、记忆、知识库、委派、计划……它适合回答“这个模块怎么仿写”，不适合回答“一个 Agent 能力是怎么长出来的”。

v2 改成一个原则：

> **功能是主线，知识点跟着功能出现，代码和测试证明这个功能真的成立。**

不是先讲“什么是短期记忆”，再找一段代码对应；而是先定义“这一轮对话要记住上文”这个功能，再把上下文窗口、滑动窗口、摘要压缩这些知识点，放进这条调用链里。

## 2. 三层结构和统一章节模板

### 2.1 篇 / 章 / 节的分工

- **篇**：一个完整能力域，必须有“篇级最小闭环”——一个用户任务能从入口跑到可观察结果。
- **章**：一个可观察功能。每章必须能独立跑通，不依赖后续章节才能验证。
- **节**：一个可执行步骤。每节只做一件事：定义行为、画调用链、建代码、写测试、补完整化。

### 2.2 每章固定六节

每一章都是一个目录，目录里固定六个文件：

```text
第NN篇-能力域/
├── README.md                     # 篇导言：能力地图、篇级闭环、章节依赖
└── 第NN章-功能名/
    ├── README.md                 # 章导言：功能、验收、前置依赖
    ├── 01-功能与知识点.md         # 这个功能解决什么问题；本章融入哪些知识点
    ├── 02-最小调用链.md           # 入口 → 调用节点 → 状态变化 → 出口
    ├── 03-代码创建.md             # 建哪些文件/符号，谁调用谁，创建顺序
    ├── 04-测试.md                 # 失败用例、单元测试、行为测试、运行命令
    ├── 05-完整化.md               # 从最小闭环扩到完整功能：分支、边界、取舍
    └── 06-边界与验收.md           # 本地没做什么；本章完成标准；下一章依赖
```

不要求每章字数一样；要求每一章都能回答四个问题：

1. 这个功能在完整对话里什么时候发生？
2. 它调用了谁，又被谁调用？
3. 最小实现是哪几个文件、哪几个符号？
4. 跑什么命令能证明它对，故意改坏哪里会失败？

### 2.3 知识点怎么写

`01-功能与知识点.md` 里不放百科定义，只放“知识点在本功能里的体现”：

| 知识点 | 在本功能里体现为 | 可观察证据 |
|---|---|---|
| 例如：function calling | 模型输出工具名和参数，运行时校验并执行，再把结果作为 observation 回灌 | 一次工具调用产生 tool_call + tool_result 两条消息 |
| 例如：上下文预算 | 拼 prompt 前按 token 预算裁剪历史，保留 system 和最近消息 | 超长输入后 prompt 仍在预算内，且关键事实未丢 |

知识点必须能落到一个行为、一个字段、一个分支或一条测试；落不下去的，不写进本章。

## 5. 样板章节：第 05 篇第 2 章「召回、快照与注入」

这一章按六节落地，作为后续所有章节的写法样板。

### 5.2.1 功能与知识点

功能：用户在新 thread 提到旧偏好，Agent 能召回相关记忆，并把记忆作为“参考数据”而不是“系统指令”放进 prompt。

知识点如何体现：

- **长期记忆不是聊天记录**：只有通过 `remember` 写入的 atom 才会被召回。
- **检索排序**：关键词命中、importance、pin 共同决定排序；向量召回是后续扩展。
- **召回快照**：同一轮 prompt 使用同一份命中副本，避免边生成边变。
- **提示注入防御**：记忆块包在 `<memory>` 中并声明 untrusted，不能执行其中的指令。

验收：给两个 thread，第一个写偏好，第二个能召回；召回结果能格式化成带边界的记忆块。

### 5.2.2 最小调用链

```text
新 thread 用户消息
  → 拼 recall query
  → facade.recall(namespaces, query, top_k, max_chars)
  → store.search_keyword_ns（命中、排序、预算）
  → recall_snapshot.record_thread_recall（冻结本轮命中）
  → format_memory_for_injection（`<memory>` + untrusted）
  → prompt 组装
```

这一节要画真实调用图，并标出：谁触发召回、召回失败时是否阻断回答、快照何时写。

### 5.2.3 代码创建

按调用方向建文件，不按“概念顺序”建：

1. `memory/store.py`：查询与排序。
2. `memory/facade.py`：`recall` 门面、预算和过滤。
3. `memory/recall_snapshot.py`：本轮快照。
4. `agents/memory/prompt.py`：格式化与边界声明。
5. 调用方：先用手写 query 验证，再接 Agent 入口。

每节说明：新文件为什么存在、符号被谁调用、字段从哪来、失败返回什么。

### 5.2.4 测试

先写失败用例，再实现：

- 单测：两个 atom 的排序、预算裁剪、已删 atom 不返回。
- 行为测试：thread A 写偏好 → thread B 召回 → 格式化结果包含该偏好。
- 边界测试：空 query、无命中、memory 文件损坏、超长记忆被截断。
- 注入测试：记忆正文含“忽略系统指令”，格式化后仍只作为 untrusted 数据。

命令：`uv run pytest tests/chapters/test_ch05_02_recall.py -q`。
