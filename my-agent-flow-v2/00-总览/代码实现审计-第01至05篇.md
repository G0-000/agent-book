## 1. 结论

**没有一章达到“五篇范围内的完整实现”。**

审计基线：3 章有组件闭环（`01.4` 单轮图、`03.1` 工具注册、`05.1` atom 写入），18 章只有局部组件，5 章未发现实现。审计后已补 R1 工具循环、R2 生命周期、R5 记忆注入、R3 上下文策略；当前为 **3 章组件闭环 / 21 章局部 / 2 章未实现**，仍然 0 章端到端完整。

最关键的三个断点：

1. `agents/lead_agent/graph.py` 现在有可选工具循环、system prompt 和 `ToolExecutor + AuditMiddleware`，但 `chat` 只注册 `echo`，策略、审批、参数校验仍未接。
2. `app/gateway/routers/chat.py` 已传 checkpointer、已写 user/assistant 消息、已注入关键词记忆，但**不回读消息表、不过上下文预算、没有策略/审批**。`/api/chat` 能保留 thread 历史，但不是“有治理的 Agent”。
3. 记忆、上下文、工具中间件、审批、分享仍是“可单独测试的组件”，`grep` 不到它们被主 Agent 或聊天入口调用。

因此 `my-agent-flow` 不是“再补几个函数”，而是要把**运行时主线**重做出来。

## 3. 第 05 篇专项

第 05 篇 5 章里，只有 **05.1 写入**是组件闭环；其余是“有零件，没有装配”。

- **05.2**：`recall`、`format_atoms_block`、`record_thread_recall` 通过 `memory/injection.py` 接进 `/api/chat`，system prompt 已有 memory 段；但只关键词召回、固定 `user:default`，无向量/混合/权限，不能声称“多用户长期记忆完整”。
- **05.3**：`consolidate_namespace` 能合并同 subject/相似 atom，也能保 pin；但没有过期、审计、撤回入口，“治理”只完成一半。
- **05.4**：本地没有 `agents/memory/queue.py`、`updater.py`，也没有防抖/LLM 抽取/schema 校验。EvoFlow 的 `MemoryUpdater` 链没有复刻。
- **05.5**：artifact 契约和 items CRUD 存在；`items.list_items` 的 `filter_visibility` 是明确的 no-op，artifact 未接聊天，reflection 未接主流程。

第 05 篇要真正闭环，至少需要一条这样的链：

```text
/api/chat
  → 读 thread task memory
  → 构造 query
  → facade.recall(namespaces, query)
  → format_atoms_block / format_memory_for_injection
  → 作为 system 段注入
  → 回答后按策略抽取 atom
  → 防抖入队
  → 巩固/治理
  → 写回并记快照
```

## 4. 根因

不是“缺某个工具函数”，而是缺三层装配：

1. **没有 AgentRuntime**：模型、Prompt、工具、记忆、预算、checkpointer 没有统一编排入口。
2. **聊天状态只接了一半**：`/api/chat` 已传 checkpoint、写消息表、登记 run，但不回读消息表，三套状态仍未统一。
3. **组件按章建，没有按调用链建**：每章都能单独过测试，但没有任何一条链把它们串起来。
